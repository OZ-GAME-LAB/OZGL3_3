# 대화 순서 테스트 씬

`Assets/01_Scenes/DialogueTest.unity`를 열고 Play를 누른다. 플레이어 이동이나 전투 없이 현재 JSON의 모든 대사를 확인하는 전용 씬이다. 권장 Game View 비율은 16:9다.

## 배치

- 대화 그룹 27개를 각각 별도 오브젝트로 배치했다. 리아 → 에단 → 오르벤 → 에단 → 리아처럼 같은 NPC가 다시 나오는 위치에도 NPC 프리팹 인스턴스를 따로 놓았다.
- 각 비반복 대화 뒤에는 실제 TriggerId를 표시하는 자동 트리거 오브젝트 21개를 배치했다. 보라색 표식이며 해당 대화를 완료하면 발생 상태가 바뀐다.
- 두 전투 구역에는 주황색 전투 완료 이벤트 오브젝트를 배치했다. 이 버튼은 몬스터 담당 시스템의 완료 보고를 대신 실행한다.
- 총 50개 순서 오브젝트가 번호와 화살표를 따라 좌우로 번갈아 이어진다. Hierarchy의 OrderedDialogueStations도 같은 순서다.
- 모든 오브젝트 상단에 역할·그룹 ID·조건 ID 또는 이벤트·트리거 처리 내용을 임시 TMP 텍스트로 적었다. 원래 게임용 NPC 프리팹에는 이 텍스트를 추가하지 않았다.

## 조작

| 조작 | 동작 |
| --- | --- |
| 다음 순서 실행 | 아직 확인하지 않은 대화·수동 이벤트 중 현재 조건에 맞는 다음 순서를 실행 |
| 오브젝트의 이 순서 실행 | 그 위치의 대화 또는 수동 이벤트 실행 |
| Enter | 대사 표시 완료 → 다음 대사. 대화 중이 아니면 다음 순서 실행 |
| 이전 위치 / 다음 위치 | 카메라만 이동. 진행 상태는 변경하지 않음 |
| 좌우 방향키 | 이전·다음 위치로 카메라 이동 |
| 전체 배치 | 50개 순서의 전체 배치 보기. 이전·다음 위치를 누르면 다시 가까이 보기 |
| 처음부터 | 테스트 진행을 초기화하고 첫 리아 대화 위치로 이동 |
| 이 대화 완료 | 현재 대화 그룹을 완료 처리. 실제 Skip과 동일하게 진행 트리거 적용 |
| 진행 없이 중단 | 대화를 닫되 완료·보상을 적용하지 않음 |

**조건 무시 개별 보기**를 켜면 위치를 고르고 원하는 대화를 바로 볼 수 있다. 이 모드는 선택한 그룹만 재생하며 자동 후속 그룹은 이어 재생하지 않는다. 별도 DialogueService와 사용자 데이터로 실행하므로 정상 진행 테스트의 플래그·완료 이력·이벤트는 바뀌지 않는다. 이 모드에서는 수동 전투 완료 이벤트를 실행하지 않는다.

반복·선택 보고 대화도 데이터에서 가능한 시점에 순서대로 끼워 넣었다. 정상 진행에서 반복 그룹을 한 번 끝내면 확인 완료로 표시한다. 다시 보고 싶다면 개별 보기 모드를 사용한다.

## 이벤트 확인

1. 숲 또는 유적의 전투 전 안내를 완료한다.
2. 이어진 보라색 자동 트리거 표식이 완료됐는지 확인한다.
3. 바로 다음 주황색 전투 완료 이벤트의 실행 버튼을 누른다.
4. 실제 EventId를 기록하고 후속 대화를 대기 목록에 넣는다. 다음 프레임에 전투 후 대사가 자동으로 재생된다.
5. 기록물 조사 NPC로 이어 간다. 전투 완료를 보고하지 않으면 후속 대화와 조사는 조건 대기 상태로 남는다.

오른쪽 패널에는 현재 위치의 실제 조건 체인과 최근 트리거·이벤트가 표시된다. 자동 트리거는 앞 대화가 끝날 때 발생하므로 표식에 수동 실행 버튼을 활성화하지 않았다. 엘린의 최종 보고 뒤 MS_OUTRO가 자동으로 이어지는 것도 실제 JSON의 NextDialogueGroupId를 그대로 사용한다.

## 기존 게임과의 분리

- 실제 DataTableManager와 DialogueService로 프로젝트의 JSON을 읽고 조건·대화 진행·트리거·자동 후속 대화를 처리한다. 테스트 코드에 개별 TriggerId의 효과를 다시 구현하지 않았다.
- 테스트 저장은 프로젝트의 `Temp/DialogueTestScene/<세션 ID>`에만 생성한다. Play를 새로 시작하거나 처음부터 버튼을 누르면 새 세션이 만들어진다. `Assets/UserData`는 읽거나 수정하지 않는다.
- GameManager·플레이어·몬스터를 씬에 넣지 않았다. NPC와 이벤트 프리팹의 게임용 연결 컴포넌트는 이 테스트 씬의 인스턴스에서만 껐다. 원본 프리팹은 그대로다.
- 조건대로 진행하는 모드는 정상 테이블을 사용하고, 개별 보기 모드는 별도로 로드한 테이블 복사본의 조건과 자동 연결만 해제한다. 원본 JSON·엑셀은 변경하지 않는다.
- 이 씬은 대사와 데이터 흐름을 확인한다. 실제 이동·Collider 진입·몬스터 전투 완료 판정까지 검증하는 씬은 아니다.

## 추가한 파일

- `Assets/01_Scenes/DialogueTest.unity`: 순서별 NPC·이벤트·자동 트리거 50개와 테스트 UI
- `Assets/02_Scripts/Tests/DialogueTestScene.cs`: 독립 테스트 세션, 데이터 진행, 카메라 이동, 미리보기와 UI
- `Assets/02_Scripts/Tests/DialogueTestStation.cs`: 각 순서 오브젝트의 ID·종류·실행 버튼·상태 표시
- `Assets/03_Prefabs/NPC/Tests/DialogueTestStation.prefab`: 테스트 순서 오브젝트 공통 프리팹
- 같은 폴더의 DialogueTestFont.asset, DialogueTestSelection.png: 테스트 표시용 폰트와 선택 배경

중앙 제어 스크립트 하나와 순서별 표시 컴포넌트로 나눠, 기존 게임 코드나 NPC 상호작용을 변경하지 않고 테스트할 수 있게 했다. 장점은 실제 데이터 로직을 사용하면서 기존 저장과 이동 시스템에 영향을 주지 않는다는 점이다. 단점은 대화 그룹을 추가·삭제하거나 순서를 바꾸면 테스트 씬의 순서 오브젝트 구성도 갱신해야 한다는 점이다. 대사 본문과 기존 그룹의 조건 값 수정은 다음 Play부터 그대로 읽는다.
